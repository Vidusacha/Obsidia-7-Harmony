# Git Documentation Pre-Push Rule

Before executing any `git commit` or `git push` command on the repository `https://github.com/Vidusacha/Obsidia-7-Harmony`, the AI agent **MUST ALWAYS** inspect and update the project documentation files to ensure they accurately reflect the latest code state, architectural decisions, and development progress:

1. **`concept.md`**: Update if core project strategy, narrative lore, or meta-goals changed.
2. **`design.md`**: Update if UI design, visual aesthetics ("Riveting-Punk"), shaders, or block geometry specs changed.
3. **`gameplay.md`**: Update if physics laws, Kirchhoff solver equations, gas reactivity, energy maintenance, or survival formulas were modified.
4. **`development_plan.md`**: Mark completed task checkboxes, add new checklist items, and record current milestone status.
5. **`audit.md`**: Log all new decisions, architectural changes (ADRs), user side-requests, and distilled context notes.
6. **`architecture.md`**: Update if module interfaces, Headless Core APIs, BCC lattice math, or Ollama REST endpoints were changed.
7. **`README.md`**: Ensure setup steps, project links, and file index remain up to date.

**Execution Directive**: Verify and edit these markdown files BEFORE executing `git commit` or `git push`.
